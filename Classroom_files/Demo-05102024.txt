What is the different between manual testing and automation testing ? 
As we are here to learn cypress automation tool, we need to understand what is automation testing ?
Suppose If you do have 2000 test cases as part of regression testing ?

Regression testing : Whenever there is a change or update or improvement with in the application we need to make sure there is no impact of this implementation on existing features or already tested feature.
to do so we need to conduct testing on all impacted areas of the application for the above code changes as part of improvements/updates. 

2000 Regression test case that means , if there any change in the exist code there is need of executing 2000 tests to make sure there is no impact on already released features.

to do we need to 10 testers for 2 weeks. 
but there is no that much time to execute regression suite , then can we ignore this regression ? 

how to execute 2000 regression tests in 2 days of time ? 

less time more outcome and less resources I do not want to allocate manual testers to do that job. 

We need to introduce automation tool to solve the above problem.

Smoke testing -  conduct highlevel testing on imp feature on every new build to accept the build or reject.
ensuring the stability of build to conduct further testing 

we are transferring manual Burdon on a tool.

Manual testing : we need to examine the application with testers knowledge and naked eye. 
testers are using their knowledge to make sure is this working fine or not. he only experience with his naked eye.

You are paid resource for your work. 

we need to automate the testers knowledge and experience with the help of any automation tool.

As tool is not an intelligent , we need to train the tool to do your work.  

how train the tool 

1. where is UI component  => example where we can find username in the web application , an automation tester need to train your automation tool to do this activity 
we can call it as locate the element by using locators or selectors. 

locators in selenium  => 

2. What kind of action we are able to perform on this located component 
textbox  =>  type the text 
clear the text 
slowly type the text
quickly type the text 
using back space remove the text 

3. What kind validations or checks we need to perform on this Located or selected UI component . 

Expected result == Actual result  => if it is true then test pass 
expected result != actual result  =>  test fail 
automatically tool will create a defect based on your training 

example : typed text should be present on the Username textbox 
this field name is Username textbox or not 

generate the reports, howmany tests are pass /fail / pending to execute or hold . 


rerun 2000 test cases without having any new testers , we can run and experience the test report . 

we do invest time in converting the manual tests into automation tests.

this is nothing but train the tool to do your work - one time activity.

run and experience the results -  without any bias => get the report in your inbox.

when to automate ?

Regression suite and smoke suite we are re running for every build and every release. 

whenever we do execute test cases very frequently - same tests - then those test cases qualified for automation. 

we do have a test case where it is changing very frequently . this feature is not qualified for automation. 

a. repeatedly we need to execute those tests -  smoke and regression 
b. there should not be any human intervention related activities
captcha and otps 

10% features do not ready for automation - 

either we frequently changing the behavior of the feature because of the competitive ness
or human intervention on this feature 


Note:  Eventhough we do automate application tests , we can never ignore manual testing.
